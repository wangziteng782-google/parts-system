## 重要坑：LongCat 推理模型
- LONGCAT 用的是 **LongCat-2.0 推理模型**：先输出 `reasoning_content`（思考）再输出 `content`（正式答案）。
- 若 `max_tokens` 太小（原 256），思考耗尽 token 导致 `content` 为空，只能取到思考过程 → 接口返回一堆"思考"。
- 修复：`_call_ai_chat` 默认 `max_tokens=1024`（ai-compare 用 1536），且**只取 `content`**，不再回退 `reasoning_content`。改动已生效并验证。
- 备忘：以后加新 AI 功能，`max_tokens` 必须留足（>=1024），并只用 `content` 字段。

## 修复：AI 输出错别字导致内容丢失（改用 JSON 结构化输出）

- 现象：LongCat 偶发把「替代理由」写成「替理由」，正则标签匹配失败 → 该段内容丢失。
- 根治方案：让 AI 返回 **JSON**，键名用英文简写（models/reason 等），后端 `json.loads` 解析后映射回中文标签。
- 新增辅助函数（sales.py）：
  - `_parse_ai_json(content, fields)`：剥离 markdown 代码块/截取 `{...}` 后 json.loads，转 `{中文标签: 内容}`，失败返回 None。
  - `_format_sections(data)`：转回「标签：内容」分段文本（前端 `renderAiSections` 零改动）。
  - `_run_ai(messages, json_fields, text_labels, max_tokens)`：优先 JSON，失败回退 `_extract_labeled_sections` 正则。
- 5 个接口（ai-explain/compare/quote/substitute/match）全部改为 JSON prompt + `_run_ai` 调用。
- 实测：替代型号连续 3 次、其余 4 接口均返回干净结构化内容，无错别字、无思考混入。前端无需改动。

## 重要坑：重启服务时端口占用
- 多次出现「新服务启动失败（Errno 10048 端口占用）」，原因是 kill 的 PID 不是真正监听 8055 的进程。
- 正确做法：先 `netstat -ano | grep ':8055' | grep LISTENING` 拿到真实 PID，`taskkill /F` 该 PID，确认端口释放后再启动。
